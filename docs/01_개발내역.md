## 1. 배경과 목표

금융·레거시 환경의 C/C++ 소스는 CP949 인코딩, 사내 메모리 매크로, 긴 단일 `.cpp` 파일이 흔하다.  
클라우드 LLM에 소스를 올리지 않고, **로컬 Ollama + 정적 힌트(cppcheck/정규식) + Streamlit 리포트**로 수정 포인트를 뽑는 것이 1차 목표였다.

핵심 원칙:

1. 소스는 PC 밖으로 나가지 않는다.
2. 원본 파일은 수정하지 않고, 임시 가공 후 리포트만 생성한다.
3. 파일 전체 통째 분석 대신 **함수 단위 청크**로 순차 검토한다.
4. LLM 출력은 JSON으로 강제하고, Before/After 스니펫을 포함한다.

## 2. 아키텍처 요약

```text
[소스 업로드 / 프로젝트 루트]
        │
        ▼
[인코딩 정규화: utf-8 → cp949 → euc-kr]
        │
        ├─► cppcheck (있으면) ──► 경고 힌트
        ├─► 정규식 suspects ──► memset/sizeof/sprintf 확정·강력 의심
        └─► 함수 청크 + [L000n] 줄번호 주입
                │
                ▼
        Ollama(qwen2.5-coder) JSON 분석
                │
                ├─► (옵션) 교차 검증 모델
                └─► (옵션) 문장 정리 모델
                        │
                        ▼
        Streamlit 결과 + reports/*.md, *.csv
```

주요 모듈:

| 파일 | 역할 |
|------|------|
| `app.py` | Streamlit UI, 옵션 다이얼로그, 화면 탭 |
| `reviewer.py` | 검토 파이프라인, Ollama 호출, 진행률 |
| `analyzer.py` | cppcheck 연동 |
| `chunks.py` | 함수 단위 분할 |
| `suspects.py` | memset/sizeof/sprintf 정적 의심 |
| `headers.py` / `symbol_index.py` | 헤더·심볼 인덱스 |
| `samples_db.py` | few-shot 샘플 DB (키워드+벡터 하이브리드) |
| `vector_store.py` | Chroma 3컬렉션 + BGE-M3 CPU 임베딩 |
| `whitelist.py` | 초기화 인정 함수/진입 함수 |
| `report.py` | MD/CSV 리포트 저장 |
| `hardware.py` | VRAM/RAM 기준 모델 권장 |
| `cpu_meter.py` / `gpu_meter.py` / `sys_panel.py` | 안내 패널 메트릭 |

## 3. 개발 단계별 내역

### 3.1 분석 엔진 (코어)

- Ollama 로컬 호출 (`temperature=0`, `num_ctx=4096`, JSON format)
- 하드웨어 프로필별 권장 모델 (`hardware.py`)
- CP949/EUC-KR 로더, 줄번호 주입, 함수 청크
- cppcheck 연동 + cppcheck 없을 때 정규식 폴백
- suspects: `memset(ptr, sizeof(ptr))`, 배열 decay `sizeof`, 스택 `sprintf` 넘침
- 교차 검증·문장 정리 모델(옵션)
- 진행률 표시, 발견 항목 중복 제거, Before/After 컨텍스트 채움

### 3.2 데이터·학습 보조

- `bug_samples.json` 샘플 학습 관리 UI (등록/삭제/JSON 가져오기)
- 키워드 매칭 few-shot 최대 3개 동적 주입
- 오탐 → “정상 코드로 예외 등록”
- `init_whitelist.json` 초기화 함수·진입 함수 관리
- 결과에서 화이트리스트 추가 버튼

### 3.3 헤더 인덱스

- `config/index.yaml` 헤더 루트 저장
- SQLite 심볼 인덱스 구축/증분 갱신
- 검토 시 헤더 구조체·매크로 컨텍스트 예산(토큰) 적용

### 3.4 UI (1차 마무리)

- 블랙 헤더에 제목·탭·옵션 일체화
- 안내 패널: `CPP_MEMORY_BUG_REVIEW` 커맨드센터 스타일
- 상태 패널: Ollama 연결·CPU·주소
- 검토 작업 캔버스: 업로드·루트·요청·실행 (다크 그레이)
- 옵션: 하드웨어, **공유 메모리 사용**, 모델, 토큰 상한, cppcheck 표준
- 옵션 다이얼로그는 `dlg_*` 임시 키 → 닫기 시 세션 커밋 (선택 유지)

### 3.5 GPU/시스템 메트릭

- Windows 성능 카운터: 전용/공유 GPU 메모리, 사용률
- AMD ADL: GPU 온도
- NVIDIA: `nvidia-smi` 경로 유지
- 공유 메모리 옵션 ON 시 VRAM 아래에 GPU 공유 메모리 표시 (시스템 RAM 전체가 아님)

### 3.6 배포·운영

- `START.bat` / `REVIEW.bat` 로컬 실행
- GitHub private 동기화 (`tenard2-max/cpp-memory-bug-review`)
- 리포트 자동 저장 `reports/`

## 5. 실행 방법 (요약)

1. Ollama 실행 및 `qwen2.5-coder:7b` 준비
2. (권장) cppcheck 설치
3. `START.bat` 또는 Streamlit으로 `app.py` 실행
4. 옵션에서 하드웨어·모델 확인
5. 소스 업로드 또는 프로젝트 루트 지정 후 검토 실행
6. 결과는 화면 + `reports/` 폴더
