커서(Cursor)에 붙여넣을 '샘플 코드 학습(예제 주입)' 요구사항아래 인용구 내용을 복사해서 커서 채팅창에 그대로 입력해 주세요.내가 직접 모은 'C++ 버그 샘플 코드(과거 버그 사례 및 사내 특수 패턴)'를 모델이 학습해서 똑같은 유형의 버그를 기가 막히게 잡아내도록, 'Few-Shot 예제 관리 및 동적 주입(Dynamic Few-Shot Injection)' 기능을 추가해 줘. (무거운 파인튜닝 대신 프롬프트 컨텍스트에 예제를 주입하는 방식으로 구현할 것)1. 샘플 데이터베이스(bug_samples.json) 구조 설계 및 생성프로젝트 폴더 내에 bug_samples.json 파일을 읽고 쓰는 모듈을 만들어 줘.각 샘플 항목은 다음 필드를 가져야 해id 고유 번호category 버그 종류 (예 조기 리턴 시 미해제, strncpy 널 누락, 사내 매크로 오용 등)keywords 이 샘플이 활성화될 트리거 키워드 리스트 (예 [malloc, return], [strncpy, sCardAcc])bad_code 실제 버그가 있었던 샘플 C++ 코드 조각good_code 올바르게 수정된 C++ 코드 조각explanation 왜 이게 버그이고 어떻게 잡아야 하는지 핵심 해설 (1~2줄)is_false_positive true일 경우 이 패턴은 사내 정상 코드이니 절대 버그로 잡지 마라(오탐 방지)는 네거티브 샘플로 활용2. Streamlit UI에 '샘플 코드 등록관리 탭' 추가내가 코드 파일을 열지 않고도 화면(UI)에서 바로 내 샘플 코드를 복사해 붙여넣고 저장할 수 있는 [샘플 학습 관리] 탭을 만들어 줘.기능 새 샘플 추가, 등록된 샘플 목록 보기, 삭제, JSON 내보내기불러오기.특히 '오탐(False Positive) 등록 기능'도 넣어줘. 분석 리포트에서 모델이 정상 코드를 버그라고 잘못 짚었을 때, [이 코드는 정상임(예외 학습)] 버튼을 누르면 곧바로 네거티브 샘플로 등록되어 다음부터는 같은 패턴을 지적하지 않도록 해 줘.3. 키워드 매칭 기반 '동적 예제 선택기(Dynamic Selector)' 구현 (메모리 절약 핵심)로컬 모델(num_ctx 4096)의 메모리 한계 때문에 bug_samples.json에 있는 수십 개의 샘플을 매번 프롬프트에 다 넣을 수는 없어.현재 분석 중인 C++ 함수 블록 안에 포함된 함수명이나 키워드(예 strncpy, new, SAFE_DELETE 등)를 파이썬이 먼저 스캔해서, bug_samples.json에서 가장 연관성이 높은 샘플 최대 3개만 자동으로 골라내어 시스템 프롬프트의 [참고할 사내 버그 및 예외 사례] 섹션에 동적으로 끼워 넣어 줘.4. 기본 샘플 3개 사전 탑재테스트를 위해 bug_samples.json이 없을 때 자동 생성되는 초기 데이터로 다음 3가지 C++ 레거시 단골 버그 샘플을 미리 넣어 줘함수 상단에서 mallocnew 할당 후 중간 if (err) return; 분기에서 해제 누락하는 패턴strncpy(dest, src, sizeof(dest)) 사용 후 마지막 바이트 dest[sizeof(dest)-1] = '0' 처리를 안 해서 버퍼 오버리드가 나는 패턴포인터를 free(p) 한 뒤 p = NULL 초기화를 안 하고 아래쪽 조건문에서 재사용하는 패턴이 방식이 실무에서 강력한 이유 3가지즉각적인 학습 효과 (0초 반영)새로운 유형의 버그를 발견하거나, 사내 고유의 구조체(예 theTran.APvar 등) 패턴을 가르치고 싶을 때 UI에 복사해 넣고 '저장'만 누르면, 1초 뒤 다음번 코드 분석부터 즉시 그 지식을 반영해서 똑같은 버그를 잡아냅니다.'오탐지(헛소리)' 길들이기 가능로컬 모델을 쓰다 보면 분명히 사내 매크로로 안전하게 처리된 코드인데 계속 버그라고 우기는 경우가 생깁니다. 이때 2번 요구사항에 넣은 [정상 코드로 예외 학습] 기능을 쓰면, 모델에게 이런 모양의 코드는 우리 회사에서 정상 처리된 거니까 입 다물고 넘어가라고 확실하게 교육할 수 있습니다.컨텍스트 메모리(4096) 한계 극복
