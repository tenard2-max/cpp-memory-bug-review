지금까지 논의한 모든 핵심 기능(VS 2008 인코딩 대응, 줄 번호 강제 주입, 함수 단위 쪼개기, 샘플 학습, 초기화 화이트리스트 UI, 구조체 전체 초기화 및 포인터 sizeof 버그 검증)을 하나로 완벽하게 통합한 마스터 요구사항 명세서입니다.


📋 커서(Cursor) 전달용 통합 마스터 오더 (전체 복사해서 붙여넣기)
현재 만들고 있는 '로컬 LLM 기반 레거시 C/C++(VS 2008) 메모리 및 초기화 버그 분석기' 프로젝트를 아래의 최종 통합 요구사항에 맞춰 전면 보완 및 리팩토링해 줘. 원본 파일 수정 기능은 필요 없으며, 임시 파일을 가공해 가장 정확한 '수정 포인트 리포트'를 뽑아내는 것이 유일한 목적이야.

[1] 실행 환경 및 로컬 LLM 최적화
타겟 하드웨어 호환: 내장 그래픽 노트북(Ryzen 7 5825U / 16GB RAM)과 데스크탑(GTX 1070 8GB) 모두에서 원활히 돌아가도록 Ollama 기본 모델은 qwen2.5-coder:7b로 설정하되, UI에서 모델명과 Ollama 서버 주소(http://localhost:11434 기본값, 원격 IP 변경 가능)를 바꿀 수 있게 해 줘.

Ollama 호출 옵션 강제: 파이썬에서 Ollama API 호출 시 메모리 폭주와 환각을 막기 위해 format="json", options={"temperature": 0.0, "num_ctx": 4096, "num_thread": 8}을 기본 적용해 줘.

[2] 파일 전처리 및 하이브리드 정적 분석 파이프라인
레거시 인코딩 완벽 대응: 구형 VS 2008 소스(.cpp, .h, .hpp)는 대부분 CP949(ANSI) 인코딩이야. 파일을 읽을 때 utf-8 -> cp949 -> euc-kr 순서로 디코딩을 시도하고, 그래도 깨지는 문자는 errors='replace'로 처리해서 절대 인코딩 에러로 멈추지 않게 해 줘.

함수 단위 쪼개기 (Function Chunking): 수천 줄짜리 파일을 통째로 넘기지 말고, 중괄호({ }) 짝 맞추기나 정규식을 이용해 **함수 단위(최대 150줄 이내)**로 쪼개서 순차 분석하고 화면에 진행률(Progress Bar)을 표시해 줘.

줄 번호 텍스트 강제 주입 (Line Number Injection): LLM이 줄 번호를 정확히 짚도록, LLM에 넘기는 코드 텍스트의 모든 줄 맨 앞에 [L0001] , [L0002]  형태로 원본 줄 번호를 박아서 넘겨줘.

1차 필터 (cppcheck + 파이썬 정규식 스캔):

cppcheck가 설치되어 있다면 백그라운드로 먼저 돌려 경고(메모리 누수, uninitvar, uninitStructMember, sizeof 오류 등)를 수집해 LLM에게 힌트로 함께 넘겨줘. (cppcheck가 없어도 파이썬 자체 필터로 동작해야 함)

파이썬 정규식으로 다음 패턴을 1차 스캔하여 LLM 프롬프트에 **"강력 의심 구간"**으로 강제 경고를 주입해 줘:

memset(ptr, 0, sizeof(ptr)) 패턴: 첫 번째 인자에 &가 없는데 sizeof() 안에 동일한 변수명이 들어간 경우 (memset\s*\(\s*([a-zA-Z0-9_]+)\s*,.*sizeof\s*\(\s*\1\s*\))

함수 매개변수로 선언된 배열(char buf[128])에 대해 함수 내부에서 sizeof(buf)를 호출한 경우 (Array Decay로 인해 4바이트만 잡히는 버그)

[3] '초기화 인정 함수(Whitelist)' 관리 UI 및 엄격 탐지(Strict Mode)
화이트리스트 관리 UI (init_whitelist.json):

Streamlit UI 탭(또는 사이드바)에서 **'초기화로 인정할 함수/매크로 목록'**과 **'클래스/모듈 기준 초기화 진입 함수(예: Init(), OnInitDialog(), ResetData())'**를 내가 직접 추가/삭제/저장할 수 있게 만들어 줘.

기본 등록 함수: memset, ZeroMemory, SecureZeroMemory, calloc, strcpy, strncpy, sprintf, _snprintf, memcpy, GetPrivateProfileStringAutoA

미초기화 및 구조체 전체 초기화 엄격 탐지 규칙 (시스템 프롬프트 강제):

Strict 화이트리스트 원칙: 변수/버퍼/포인터를 선언 시 즉시 초기화(= 0, = NULL, = {0,})하지 않았다면 미초기화 상태로 간주한다. 이후 변수를 읽기 전에 내가 지정한 **'초기화 인정 함수(Whitelist)'**나 직접 대입(=)을 거치지 않았다면, 설령 다른 일반 함수에 주소(&var)나 포인터로 넘겼더라도 봐주지 말고 100% '미초기화 사용(Uninitialized Read)' 버그로 잡아내라.

조건문 분기 누락: if-else, switch-case 중 단 하나의 분기에서라도 초기화가 빠진 채 아래에서 읽히면 무조건 버그로 잡아내라.

구조체 전체 초기화 강제: 로컬 구조체(STRUCT st;)나 동적 할당 구조체(malloc/new) 선언 후, = {0,} 또는 올바른 크기의 memset(&st, 0, sizeof(STRUCT))로 구조체 전체(패딩 포함)를 먼저 초기화하지 않고 곧바로 st.member = 1; 처럼 일부 멤버만 대입한 뒤 함수를 호출하거나 리턴하면 무조건 '구조체 부분 미초기화(나머지 멤버 및 패딩 쓰레기 값 방치)' 버그로 리포트해라.

sizeof(포인터) 부분 초기화 오용: 포인터 변수 p에 대해 memset(p, 0, sizeof(p))처럼 호출하면 화이트리스트 함수라도 정상 초기화로 인정하지 마라. 32비트 기준 앞 4바이트만 초기화되고 뒷부분은 쓰레기 값으로 남는 치명적 버그이므로, 반드시 sizeof(*p) 또는 sizeof(구조체타입)인지 검사하여 100% 버그로 잡아내라.

[4] '내 샘플 코드 학습(Dynamic Few-Shot Injection)' 및 관리 UI
샘플 DB (bug_samples.json) 및 관리 탭 구현:

화면에 [샘플 코드 학습 관리] 탭을 만들어서 내가 직접 버그 사례나 예외 사례를 등록/조회/삭제할 수 있게 해 줘.

데이터 필드: id, category(버그 종류), keywords(트리거 키워드 리스트), bad_code(문제 코드), good_code(수정 코드), explanation(핵심 해설), is_false_positive(오탐 방지용 정상 코드 여부)

오탐(False Positive) 원클릭 예외 학습:

분석 결과 리포트 화면에서 모델이 정상 코드를 버그라고 잘못 짚었을 때, 바로 옆의 **[정상 코드로 예외 등록]**이나 [이 함수를 초기화 화이트리스트에 추가] 버튼을 누르면 즉시 DB에 반영되어 다음 분석부터는 같은 패턴을 지적하지 않도록 해 줘.

동적 예제 주입기 (Dynamic Selector):

컨텍스트 메모리(4096) 절약을 위해 bug_samples.json 전체를 프롬프트에 넣지 말고, 현재 분석 중인 C++ 함수에 등장하는 키워드(malloc, memset, strncpy, sizeof 등)와 매칭되는 가장 연관성 높은 샘플 최대 3개만 자동으로 골라 프롬프트에 동적으로 끼워 넣어 줘.

필수 기본 샘플 4종 사전 탑재 (bug_samples.json 초기 생성용):

샘플 1: memset(pPacket, 0x00, sizeof(pPacket)) 사용으로 구조체 56바이트 중 포인터 크기인 4바이트만 초기화된 버그 (sizeof(TRAN_PACKET)으로 수정)

샘플 2: 구조체 선언 후 memset이나 = {0,} 전체 초기화 없이 일부 멤버만 값을 넣고 패킷 전송 함수에 넘긴 버그

샘플 3: 함수 상단 malloc/new 할당 후 중간 에러 처리(if (err) return;) 분기에서 해제 없이 리턴하는 메모리 누수 버그

샘플 4: strncpy(dest, src, sizeof(dest)) 호출 후 마지막 바이트 dest[sizeof(dest)-1] = '\0' 널 종료 처리를 누락한 버그

[5] 최종 리포트 출력 규격 및 파일 내보내기
리포트 필수 항목 (JSON 스키마 강제 후 테이블 및 카드 형태로 출력):

파일명 / 정확한 줄 번호 / 함수명 / 버그 카테고리 (메모리 누수, Use-After-Free, Double-Free, 버퍼 오버플로우, 미초기화 읽기, 구조체 부분 미초기화, 포인터 sizeof 오용, new/delete 불일치) / 확신도(High/Medium/Low)

현재 문제 코드 (Before): 문제가 된 줄과 전후 2~3줄 스니펫

수정 제안 코드 (After) 및 근거: 바로 복사해서 참고할 수 있는 수정 코드 예시와 1~2줄의 명확한 이유 (예: "포인터 크기(4byte)만큼만 초기화되어 뒤쪽 구조체 영역에 쓰레기 값이 남음")

리포트 자동 저장 및 다운로드:

분석이 완료되면 결과를 날짜와 시간이 찍힌 Markdown(.md) 및 엑셀 확인용 CSV(.csv) 파일로 즉시 다운로드할 수 있는 버튼을 제공해 줘.
