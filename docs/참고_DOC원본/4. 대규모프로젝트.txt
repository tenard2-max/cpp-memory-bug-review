지금 
"로컬 헤더 파일(.h, .hpp)을 참조하지 못해 구조체나 매크로를 인식하지 못하는 문제가 있어. 파이썬 백엔드와 UI를 다음과 같이 수정해 줘.

1. 프로젝트 폴더 일괄 지정 기능 추가 해줘, ..커서(Cursor)에게 당장 시켜야 할 수정 오더
지금 만드신 프로그램에 이 기능을 탑재하기 위해, 커서 채팅창에 아래 내용을 그대로 복사해서 던져주세요.

"분석하려는 C++ 소스 파일이 파일당 2만~3만 줄에 달하는 몬스터 파일들이야. 파일을 통째로 LLM에 넘기면 컨텍스트가 터지므로, 파이썬 백엔드에 다음의 '스마트 전처리 및 핀셋 추출' 로직을 추가해 줘.

1. 메모리 연산 키워드 기반 필터링 (Smart Pre-scan):

파일을 읽은 뒤, 전체 코드를 다 보내지 말고 정규식으로 malloc, new, memset, memcpy, free, delete 또는 구조체(struct) 선언 키워드가 포함된 함수/코드 블록만 자동으로 추출해 줘. 키워드가 없는 단순 반복 함수나 겟터/셋터는 과감히 분석 대상에서 제외(Pass)해 줘.

2. 함수 단위 순차 큐 (Queue) 및 진행률 바:

추출된 핵심 함수들을 순차적으로 LLM(큐원)에 전달하고, Streamlit UI에 실시간 진행률(Progress Bar)과 현재 분석 중인 함수명을 표시해 줘.

3. 대형 함수 슬라이딩 윈도우:

만약 특정 함수가 1,000줄이 넘어갈 경우, 500줄 단위로 겹치게(Overlap) 쪼개서 분석한 뒤 결과를 하나로 합쳐서 리포트해 줘."

개별 .cpp 파일 업로드 방식 외에, 프로젝트 루트 디렉토리 경로를 입력하거나 선택할 수 있는 입력 필드를 Streamlit UI에 추가해 줘.

2. 자동 헤더 의존성 스캔 (Header Dependency Lookup):

분석 대상 .cpp 파일 내에 #include "파일명.h"가 있으면, 지정된 프로젝트 폴더 내에서 해당 헤더 파일을 찾아 그 안의 struct, typedef, #define 매크로 정의 내용을 파싱해 줘.

3. LLM 프롬프트 자동 병합:

함수 단위로 쪼개어 LLM에 넘길 때, 해당 함수가 의존하는 구조체나 매크로가 헤더에 정의되어 있다면 프롬프트 상단에 **[참조 헤더 정의 Context]**로 자동 주입해 줘. 이를 통해 큐원(Qwen)이 구조체 멤버 구성을 정확히 알고 미초기화 여부를 판단할 수 있게 해 줘."
