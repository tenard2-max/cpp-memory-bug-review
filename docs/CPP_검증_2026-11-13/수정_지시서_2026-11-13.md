## 1. [P0] Linux에서 gpu_meter 임포트 가드

- **우선순위:** P0 (UI, 실행 불가)
- **프로젝트:** `D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토`
- **영향 파일:** `gpu_meter.py` 108행 부근 `@ctypes.WINFUNCTYPE(...)` 및 그 아래 `ctypes.WinDLL`. 필요하면 `sys_panel.py`의 import 순서.

### 현재 동작

모듈 최상위에서 Windows 전용 심볼을 쓴다. Linux에서 `streamlit run app.py`를 하면 `app.py` → `sys_panel` → `gpu_meter` 임포트 중:

```
AttributeError: module 'ctypes' has no attribute 'WINFUNCTYPE'
```

앱 전체가 예외 화면만 보이고, 검토 UI에 들어가지 못한다.

### 요구 동작

- `WINFUNCTYPE`, `WinDLL`, ADL/atiadlxx.dll 경로는 `sys.platform == "win32"`일 때만 정의·호출한다.
- Linux/macOS에서는 NVIDIA `nvidia-smi` 경로(`shutil.which`)만 시도하고, 없으면 빈 GPU 목록을 반환한다. 임포트 자체는 성공해야 한다.
- Windows에서의 AMD ADL 동작은 그대로 둔다.

### 수용 기준

- Linux에서 추가 심 없이 `streamlit run app.py`가 로드되고 「C++ 메모리·초기화 버그 검토」헤더와 탭이 보인다.
- Windows에서 GPU 패널이 기존처럼 동작한다(가능한 환경에서).

### Cursor 프롬프트

```
프로젝트 루트는 D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토 이다.

버그: gpu_meter.py 108행 부근이 모듈 임포트 시점에 @ctypes.WINFUNCTYPE 을 쓴다.
Linux에는 WINFUNCTYPE이 없어 streamlit run app.py 가
  AttributeError: module 'ctypes' has no attribute 'WINFUNCTYPE'
로 전체 화면이 죽는다. sys_panel.py 가 gpu_meter 를 무조건 import 한다.

요구:
- WINFUNCTYPE / WinDLL / atiadlxx.dll(ADL) 코드는 sys.platform == "win32" 일 때만
  정의하고 호출하라. Linux 임포트가 성공해야 한다.

- 수정 후 Linux에서 streamlit run app.py 가 예외 없이 로드되는지 확인하라.
```

## 2. [P0] cppcheck 발견을 결과 목록에 병합

- **우선순위:** P0 (정확성, 오판 “버그 없음”)
- **프로젝트:** `D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토`
- **영향 파일:**
  - `reviewer.py` `_findings_from_suspects`, `_merge_suspects`, `review_paths` (451–494행 부근)
  - 필요하면 `analyzer.py`의 이슈 → finding 변환

### 현재 동작

`prepare_review`는 cppcheck 경고를 받아 청크 힌트와 `result["report"]`에는 넣지만, 모델이 `findings: []`를 주면 그 경고는 최종 목록에 들어가지 않는다. `_merge_suspects`가 다시 붙이는 것은 `suspects.py`가 확정한 memset/sprintf 줄뿐이다.

측정: `samples/use_after_free.cpp`에서 cppcheck는 `deallocuse`(해제 후 역참조)를 내지만, 빈 LLM 응답으로 `review_paths`를 돌리면 findings 0건이고, UI는 「보고할 메모리 버그와 초기화 버그가 없습니다 / 발견 0건」이다. 누수·이중 해제·미초기화·new/delete 불일치도 같은 방식으로 사라진다. sprintf/sizeof 패턴만 남는다.

### 요구 동작

- cppcheck 메모리 이슈를 `findings` 항목으로 변환한다(bug_type 매핑: deallocuse→use_after_free, doubleFree/deallocDealloc→double_free, memleak→memory_leak, uninitvar→uninitialized_read, mismatchAllocDealloc→new_delete_mismatch, bufferAccessOutOfBounds/arrayIndexOutOfBounds→buffer_overflow, dangling*/returnReference→dangling_pointer 등).
- 모델 findings와 **줄+종류 기준으로 병합**한다. 모델이 비우거나 거절·JSON 실패여도 cppcheck·suspects 항목은 남긴다.
- UI/CLI는 이 병합 목록을 보여 준다. “발견 0건”은 정적 힌트와 모델이 모두 비었을 때만 쓴다.
- 확신도: 정적 확정은 high, cppcheck는 기존 심각도에 맞게 high/medium.

### 수용 기준

- `samples/use_after_free.cpp`를 모델 없이(또는 빈 응답 모의로) 검토하면 해제 후 사용이 최소 1건 보고된다. 「버그 없음」이 아니다.
- K01 누수, K02 이중 해제, K04 sprintf, K08 sizeof도 정적 경로만으로 TP.
- 정상 N01 malloc/free 올바른 쌍은 오탐이 없어야 한다.
- 기존 suspects 병합과 중복 제거(`_dedupe_findings`)는 유지.

### Cursor 프롬프트

```
프로젝트 루트는 D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토 이다.

버그: reviewer.py 의 review_paths 는 cppcheck 경고를 프롬프트/리포트 문자열에만 넣고,
최종 findings 에는 넣지 않는다. _merge_suspects 가 붙이는 것은 suspects.py
(memset sizeof / 스택 sprintf) 뿐이다. 모델이 findings: [] 를 반환하거나
JSON을 비우면 samples/use_after_free.cpp 처럼 cppcheck 가 deallocuse 를
낸 파일도 UI에 「보고할 메모리 버그와 초기화 버그가 없습니다 / 발견 0건」으로 나온다.

요구:
- analyzer.run_cppcheck 가 남긴 메모리 이슈를 bug_type 으로 매핑해 findings 에 넣어라.
  예: deallocuse→use_after_free, doubleFree/deallocDealloc→double_free,
  memleak/memleakOnRealloc→memory_leak, uninitvar/uninitdata→uninitialized_read,

- 모델 결과와 줄+종류로 병합·중복 제거하라. 모델이 비어도 정적 항목은 남긴다.
- 「버그 없음」은 정적+모델이 모두 비었을 때만 표시하라.
- Ollama를 새로 설치하거나 외부 API를 붙이지 마라. 정적 경로만으로
  use_after_free.cpp, 누수/이중해제/sizeof 샘플이 보고되는지 확인하라.
```

## 3. [P1] MEMORY 필터에 누락된 cppcheck ID를 추가

- **우선순위:** P1 (정확성)
- **프로젝트:** `D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토`
- **영향 파일:** `analyzer.py`의 `MEMORY_IDS`, `MEMORY_WORDS`, `_is_memory_issue`.

### 현재 동작

cppcheck는 `K07_dangling_ref.cpp`에서 `returnReference: Reference to local variable returned`를, sizeof 오용에서 `pointerSize: Size of pointer used instead of size of its data`를 낸다. 그러나 `MEMORY_IDS`에 두 ID가 없고, `MEMORY_WORDS`의 `dangling`/`sizeof`에도 메시지가 안 걸려(`sizeof`가 아니라 “Size of”, “Reference to local…”) **「메모리 관련 cppcheck 경고 없음」으로 버려진다.** sizeof는 suspects가 보완하지만, 댕글링 참조 반환은 정적 경로에서 완전히 사라진다.

### 요구 동작

- `returnReference`, `pointerSize`, 필요하면 `returnTemp`, `danglingTemp`, `autovarInvalidDeallocation` 등 수명·크기 관련 ID를 `MEMORY_IDS`에 넣는다.
- 메시지 단어만으로 놓치지 않게 ID 우선으로 판정한다.
- 항목 2의 병합과 함께 적용한다.

### 수용 기준

- 지역 변수를 참조로 반환하는 파일에서 프로젝트 정적 경로가 dangling 계열을 보고한다.
- `memset(p, 0, sizeof(p))`는 필터만으로도 메모리 이슈로 남는다(suspects와 중복되어도 된다).
- unusedStructMember 같은 style 경고는 계속 제외.

### Cursor 프롬프트

```
프로젝트 루트는 D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토 이다.

analyzer.py 의 MEMORY_IDS / MEMORY_WORDS 가 cppcheck 의 returnReference 와
pointerSize 를 걸러 버린다. 원본 cppcheck 는
  returnReference: Reference to local variable returned
  pointerSize: Size of pointer 'p' used instead of size of its data
를 내지만, 프로젝트 필터는 「메모리 관련 cppcheck 경고 없음」으로 만든다.
sizeof 오용은 suspects.py 가 보완하지만 댕글링 참조 반환은 정적 경로에서 사라진다.

요구:
- returnReference, pointerSize 및 동등한 수명/크기 ID를 MEMORY_IDS 에 추가하라.
- unusedStructMember, knownConditionTrueFalse 같은 비메모리 style 은 계속 제외하라.
- 지역 변수 참조 반환 샘플과 memset(p,0,sizeof(p)) 샘플로 필터가 이슈를 남기는지 확인하라.
```

- **우선순위:** P1 (사용성·정확성)
- **프로젝트:** `D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토`
- **영향 파일:** `cli.py`, `app.py`(검토 버튼 `disabled=not online or model_missing`), `reviewer.py` `review_paths`.

### 현재 동작

Ollama가 없으면 `review_paths`가 `_ollama_chat`에서 바로 `ReviewError`를 던진다. 이미 구한 cppcheck/suspects/청크는 버려진다. UI 검토 버튼은 비활성화된다.

### 요구 동작

- Ollama에 연결할 수 없으면 에러로 전체를 중단하지 말고, **정적 발견만으로 리포트**를 만들고 그 사실을 명시한다(「모델 없이 cppcheck·정규식 결과만 표시」).

- 모델이 있는 Windows 실사용 경로는 기존처럼 LLM+정적을 쓴다.

### 수용 기준

- Ollama를 끈 채 `py -3 cli.py samples/use_after_free.cpp`가 0이 아닌 발견 또는 최소한 cppcheck/suspects 리포트를 저장하고, 종료 코드로 “설정 오류만” 숨기지 않는다(발견이 있으면 성공으로 저장).
- UI에서 오프라인에도 업로드 후 검토가 실행된다.

## 6. [P2] .clang-tidy 파이프라인 연결 또는 문서화

- **우선순위:** P2
- **영향 파일:** `.clang-tidy`, `analyzer.py` 또는 README/`docs`. 문서 DOC/1은 VS 2008 때문에 cppcheck를 주력으로 쓰라고 되어 있다.

### 현재 동작

`.clang-tidy`는 `clang-analyzer-*`, `bugprone-*`를 켜지만 검토 파이프라인은 호출하지 않는다. 박스에서 같은 설정으로 돌리면 UAF·누수·댕글링·sizeof를 잘 잡는다.

### 요구 동작

둘 중 하나.

- **방안 A:** clang-tidy가 PATH에 있을 때만 선택 실행하고, 나온 메모리 경고를 cppcheck와 같이 병합한다. 없으면 건너뛰고 기록만 남긴다.
- **방안 B:** README에 “로컬 검토 파이프라인은 cppcheck만 쓰고, .clang-tidy는 IDE/에이전트용”이라고 명시한다.

### Cursor 프롬프트

```
프로젝트 루트는 D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토 이다.
.clang-tidy 는 clang-analyzer-* 와 bugprone-* 를 켜지만 analyzer/reviewer 는
clang-tidy 를 호출하지 않는다.

할 일: (A) clang-tidy 가 설치되어 있으면 선택적으로 실행해 메모리 경고를
cppcheck 결과와 병합하거나, (B) README/docs 에 파이프라인 미사용(IDE용)이라고
명시하라. VS 2008 소스에서 compile_commands 없이 실패하면 건너뛰고 이유를 남겨라.
필수 의존성으로 clang-tidy 를 추가하지 마라.
```

## 7. [P3] bug_samples.json 6번 항목 정리

- **우선순위:** P3
- **영향 파일:** `bug_samples.json` id 6 (`scrat(logBuffer, abc);`). 설명이 중간에 끊기고, 식별자가 선언되어 있지 않으며 `scrat`는 `strcat`/`sprintf` 오기로 보인다.

컴파일·정적 분석이 불가능해 few-shot 품질이 떨어진다. 완전한 함수로 다시 쓰거나, 불능 샘플이면 삭제한다.

### Cursor 프롬프트

```
프로젝트 루트는 D:\AI실무활용(제미니)\CPP_메모리버그_로컬검토 이다.
```
